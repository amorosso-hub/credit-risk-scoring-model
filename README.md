# HCIS: 신용평가 모델링 및 점수 체계 개발

> 고객의 부도 확률을 예측하고, 이를 설명 가능한 신용 점수와 대출 심사 기준으로 연결한 프로젝트입니다.

**HCIS(Home Credit Inclusion Score)** 는 Kaggle Home Credit Default Risk 데이터를 활용해 개발한 프로젝트 자체 신용 점수 체계입니다. 고객의 재무 정보와 금융 이용·상환 이력을 함께 분석하여 부도 확률(PD)을 예측하고, 이를 심사에 활용할 수 있는 점수로 변환했습니다.

승인·추가 검토·거절의 세 가지 심사 구간을 설계하고, SHAP 기반 위험 요인 설명과 LLM 기반 신용 점수 개선 피드백을 제공하여 **리스크 관리와 금융 포용성을 함께 고려하는 심사 지원 방식**을 제안합니다.

| 데이터 | 주요 분석 내용 |

| 외부 금융기관 거래 및 월별 이력 | 연체 경험의 존재 여부, 지속성, 최근성 |
| 과거 대출 신청 이력 | 신청 빈도, 반복 거절, 신청 조건의 변화 |
| 대출 상환 내역 | 지연 상환 빈도, 연체 기간, 정상 상환과의 차이 |

변수의 의미와 거래 특성을 기준으로 전처리 규칙을 수립했습니다.

- 결측이 고객의 상태나 금융 이용 이력과 관련될 수 있다고 보고, 비무작위 결측 가능성을 고려했습니다.
- 알 수 없는 범주인 XAP, XNA, Unknown 등은 특이사항이 없는 경우 결측값으로 처리했습니다.
- 파생변수의 의미에 맞게 최솟값, 최댓값, 평균, 중앙값 등을 활용해 이력을 집계했습니다.
- 날짜 관련 이상값은 도메인 기준에 따라 검토하고 클리핑했습니다.
- 음수로 기록된 상환 금액은 프로젝트 전처리 규칙에 따라 0으로 치환했습니다.
- 성별 등 차별 가능성을 고려한 일부 변수를 제외했습니다.

파생변수는 외부 평점, 부채 부담, 소액·소비 대출, 인구통계, 고용 안정성 등 의미 단위의 그룹으로 구성했습니다.

## 변수 선정과 모델링

### 1. LightGBM 기반 변수 선정

Gain Importance, Permutation Importance, SHAP를 활용해 변수의 중요도를 비교했습니다. Gain Importance의 편향 가능성을 검토하기 위해 이를 제외한 추가 실험도 수행했습니다.

추가 실험에서는 **Gain : Permutation : SHAP = 0 : 0.5 : 0.5**의 가중치를 적용하고, 상위 70개 변수를 사용한 모델과 180개 변수 기준 모델을 비교했습니다.

| 평가 지표 | 기준 모델 · 180개 변수 | TOP-70 · 추가 실험 |
| --- | ---: | ---: |
| ROC-AUC ↑ | 0.779212 | 0.7802 |
| PR-AUC ↑ | 0.269104 | 0.2702 |
| LogLoss ↓ | 0.239792 | 0.2395 |
| Brier Score ↓ | 0.066503 | 0.0664 |

보고된 비교 결과에서는 예측 성능을 유지하면서 **변수 수를 180개에서 70개로 약 61.1% 축소**했습니다. 위 수치는 변수 선정 단계의 결과입니다.

### 2. 모델 비교와 확률 보정

LightGBM, XGBoost, CatBoost를 비교하고, Optuna를 활용한 하이퍼파라미터 최적화와 확률 보정(Calibration)을 진행했습니다.

위험 고객을 구분하는 능력뿐 아니라 예측 확률의 정확도와 심사 정책에 따른 승인 비중을 함께 검토했습니다.

| 모델 | 확률 보정 | ROC-AUC ↑ | LogLoss ↓ | Brier Score ↓ | Approval@Cap ↑ |
| --- | --- | ---: | ---: | ---: | ---: |
| **XGBoost** | Isotonic | **0.782585** | **0.238582** | **0.066319** | 0.846916 |
| LightGBM | Isotonic | 0.782407 | 0.238629 | 0.066325 | **0.847781** |
| CatBoost | Isotonic | 0.779631 | 0.239365 | 0.066404 | 0.845135 |

*Notion에 기록된 Calibration 이후 평가 결과입니다. Approval@Cap은 프로젝트에서 설정한 리스크 상한 조건의 승인 비중 지표입니다.*

XGBoost가 ROC-AUC, LogLoss, Brier Score에서 가장 좋은 값을 보여 최종 모델로 선정했습니다. Approval@Cap은 LightGBM이 소폭 높아, 승인 비중과 확률 예측 성능 사이의 차이도 함께 확인했습니다.

## HCIS 점수 및 심사 기준

### 부도 확률을 신용 점수로 변환

HCIS는 모델이 예측한 부도 확률을 로그 오즈 기반 점수로 변환합니다.

$HCIS = Offset + Factor \times(ln(odds))$ **[0 ~ 1200점]**

⇒ **$Offset + \frac{PDO}{ln(2)} \times ln(\frac{1-PD}{PD})$**

- $Odds = \frac{1-PD}{PD}$
- $Factor = \frac{PDO}{ln(2)}$
- $PDO = ln(Odds) + ln(2)$
- 변수 해석
    - PD : 모델에서 추출된 각 부도 확률. 즉, 부도율
    - Odds: 부도 안 날 확률
    - PDO: Odds가 2배로 변화할 때, 점수 차이가 어느정도 나타나는 지 파악 → 실무에서는 **50**으로 설정
    - Offset: 기준 점수 (점수 분포의 중앙인 **600점**으로 설정)

| 용어 | 의미 |
| --- | --- |
| PD | 모델이 예측한 고객별 부도 확률 |
| Odds | 정상 상환 확률과 부도 확률의 비율, 즉 (1 − PD) / PD |
| PDO | Odds가 두 배가 될 때 증가하는 점수 |
| Offset | 점수 수준을 조정하는 상수 |

프로젝트 문서에서는 **Offset 600, PDO 50**을 설정값으로 제시했습니다. 이 식에서는 부도 확률이 낮을수록 점수가 높아지며, Odds가 두 배가 되면 점수가 50점 증가합니다.

### 승인·추가 검토·거절 구간 설계

점수별 위험 분포를 검토하여 약 700점을 승인 기준 후보로 고려하고, 다음과 같은 심사 비중 조정안을 제안했습니다.

| 심사 구간 | 제안 비중 | 목적 |
| --- | ---: | --- |
| 승인 | 90% | 상대적으로 위험이 낮은 고객의 심사 진행 |
| 추가 검토 | 5% | 추가 정보와 위험 요인을 확인한 뒤 판단 |
| 거절 | 5% | 위험 수준이 높은 고객군 구분 |

위 비중은 프로젝트의 **정책 설계안**입니다. 추가 검토 구간을 통해 일괄 거절될 수 있는 고객에게 재평가 기회를 제공하는 것을 목표로 했습니다.

### SHAP 기반 위험 요인 설명

각 변수에 설명용 라벨인 reason_label을 부여하고, SHAP 기반 변수 기여도를 도메인 그룹과 연결했습니다. 이를 통해 심사자가 고객의 주요 위험 요인을 파악하고 추가 검토에 참고할 수 있도록 구성했습니다.

## 개인 기여

- **데이터 전처리 및 파생변수 생성:** 데이터별 특성을 고려한 정제 규칙을 수립하고 재무 상태, 금융 이용 행태, 상환 이력 기반 변수를 제작했습니다.
- **분류 모델링:** LightGBM 기반 변수 선정과 모델 비교를 수행하고, 하이퍼파라미터 최적화 및 확률 보정을 통해 최종 모델을 선정했습니다.
- **심사 지표 설계:** 위험 구분 능력, 확률 예측 성능, 승인 비중을 함께 검토할 수 있는 평가 기준을 구성했습니다.
- **HCIS 점수 체계 설계:** 예측 부도 확률을 점수로 변환하고 승인·추가 검토·거절 구간과 설명 가능한 위험 요인 체계를 정리했습니다.

## 프로젝트 의의와 기대 효과

이 프로젝트는 부도 확률 예측 결과를 점수, 심사 구간, 위험 요인 설명으로 연결해 **모델 결과를 의사결정에 활용하는 과정**을 구현했습니다.

특히 추가 검토 구간은 상환 가능한 고객의 금융 접근 기회를 유지하고, 즉시 거절에 따른 기회 손실을 줄이기 위한 장치입니다.

예를 들어 연간 신청자 100,000명 중 5%인 5,000명을 추가 검토하고, 그중 5%를 승인한다고 가정하면 **250명의 추가 승인 기회**가 발생합니다. 이는 가정에 따른 시나리오 계산이며, 실제 운영에서 측정한 승인 증가나 수익 개선 결과는 아닙니다.
